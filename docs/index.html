Whisper on Colab for recordings that mix Korean and English 한국어와 영어가 섞인 녹음을 위한 Colab Whisper

Lectures full of English terms, meetings that switch languages mid-conversation, conference talks with a Korean host and an English speaker. This notebook transcribes that kind of audio on a free Colab T4 with faster-whisper large-v3. It splits the recording into speech chunks, picks Korean or English for each one, steers decoding toward the names and jargon you list, and saves progress so a dropped session resumes where it stopped.

영어 용어가 가득한 강의, 말하다가 언어가 바뀌는 회의, 사회는 한국어인데 발표는 영어인 컨퍼런스. 이런 녹음을 무료 Colab T4에서 faster-whisper large-v3로 전사하는 노트북이다. 녹음을 발화 조각으로 나눠 조각마다 한국어인지 영어인지 고르고, 미리 적어 둔 이름과 전문 용어를 잘 받아 적도록 디코딩을 유도하며, 진행 상황을 저장해서 연결이 끊겨도 멈춘 곳부터 다시 시작한다.

Why not just run Whisper?그냥 Whisper를 돌리면 생기는 일

Mixed-language audio is hard input for plain Whisper. A professor explains in Korean but says every technical term in English. A meeting jumps to English when an overseas colleague joins. A conference has a Korean host, an English keynote and a Q&A in both. Running the stock transcribe call with one language setting, or with automatic detection on 30-second windows, gives four recurring problems.

두 언어가 섞인 녹음은 기본 Whisper로 다루기 까다롭다. 교수님은 한국어로 설명하면서 전문 용어는 전부 영어로 말한다. 회의는 해외 동료가 들어오면 영어로 바뀐다. 컨퍼런스는 사회가 한국어, 키노트가 영어이고 Q&A는 두 언어가 섞인다. 언어를 하나로 고정하거나 30초 창마다 자동 감지에 맡겨 돌리면 아래 네 가지 문제가 반복해서 나온다.

Example: a 79-minute conference recording실행 예시: 79분 컨퍼런스 녹음

To see how it holds up on real mixed audio, I ran it on a full day of recordings from a tech conference (NVIDIA AI Day Seoul 2026): Korean host, English keynotes, Korean demos packed with English product names, and a Q&A in both languages. The run below transcribed the 79-minute plenary twice, once with large-v3 and once with large-v2, and re-did a 53-second English answer inside a mostly Korean Q&A with the language forced to English. All three ran in one Colab session on a Tesla T4. The session and control files are in examples/real-run-conference/.

실제 혼용 녹음에서 어떻게 동작하는지 보려고 기술 컨퍼런스(NVIDIA AI Day Seoul 2026) 하루치 녹음에 돌려 봤다. 사회는 한국어, 키노트는 영어, 시연은 영어 제품명이 가득한 한국어였고, Q&A는 두 언어가 섞였다. 아래 실행에서는 79분짜리 기조연설 녹음을 large-v3와 large-v2로 한 번씩 전사하고, 대부분 한국어인 Q&A 속 53초짜리 영어 답변을 언어를 영어로 고정해 다시 돌렸다. 세 작업 모두 Tesla T4 한 대로 Colab 세션 하나에서 끝났다. 세션·control 파일은 examples/real-run-conference/에 있다.

RTF is decoding time divided by audio length, so 0.114 means about seven minutes of compute per hour of audio. A fallback is a segment Whisper had to re-decode at a higher temperature because the first attempt looked repetitive or low-confidence. On this recording large-v3 was faster, needed fewer fallbacks and reported higher average log-probability than large-v2, so large-v3 is the default.

RTF는 디코딩 시간을 오디오 길이로 나눈 값이다. 0.114면 오디오 1시간에 계산이 7분 정도 든다. fallback은 첫 디코딩 결과가 반복되거나 신뢰도가 낮아서 temperature를 올려 다시 디코딩한 세그먼트 수다. 이 녹음에서는 large-v3가 large-v2보다 빠르고, fallback이 적고, 평균 log-probability도 높았다. 그래서 기본 모델을 large-v3로 두었다.

Worth knowing. With the VAD threshold at 0.35, Silero VAD marked only 871 s of the 4,743 s hall recording as speech. Most of the talk passed through the gap-filling step (--fill-gaps-s 3), which sends uncovered stretches to Whisper as well. In a large room with PA reverb and background music, check how much the VAD actually covers before trusting it alone.

포인트. VAD 임계값을 0.35로 낮췄는데도 Silero VAD는 4,743초짜리 홀 녹음에서 871초만 발화로 잡았다. 발표 대부분은 VAD가 놓친 구간을 Whisper로 다시 보내는 gap filling 단계(--fill-gaps-s 3)를 거쳐 전사됐다. 스피커 잔향과 배경 음악이 있는 큰 홀 녹음이라면 VAD만 믿기 전에 실제로 얼마나 잡는지부터 확인하는 편이 좋다.

How the pipeline works파이프라인 동작 원리

The notebook itself is short. It installs pinned packages, mounts Drive, reads the newest control_*.json, and hands off to two Python files kept on Drive. runner.py uses only the standard library and does the orchestration. stt_core.py does the transcription and runs as a separate process, so a crash inside the model still leaves a log, a status file and a zip behind.

노트북 자체는 짧다. 버전을 고정한 패키지를 설치하고, Drive를 마운트하고, 가장 최근 control_*.json을 읽은 뒤 Drive에 둔 파이썬 파일 두 개에 일을 넘긴다. runner.py는 표준 라이브러리만 써서 전체 흐름을 관리한다. 전사는 stt_core.py가 별도 프로세스로 맡는다. 그래서 모델 쪽에서 프로세스가 죽어도 로그와 상태 파일, zip은 남는다.

What runner.py does for each runrunner.py가 실행마다 하는 일

  • Copies audio/<file_id>.m4a from Drive to the Colab disk (/content/audio), which reads much faster than a mounted Drive.
  • If the run asks for an audio variant, renders it once with ffmpeg as 16 kHz mono WAV and caches it next to a sidecar file holding the filter string.
  • Measures mean and max volume with ffmpeg volumedetect and appends every stage to out/STATUS.json.
  • Starts stt_core.py with the run's flags, streams its output to the notebook and to out/<tag>/<file_id>.log.
  • After all runs, writes report_<control>.md, zips the results, triggers a browser download and unmounts Drive.
  • Drive의 audio/<file_id>.m4a를 Colab 로컬 디스크(/content/audio)로 복사한다. 마운트된 Drive에서 바로 읽는 것보다 훨씬 빠르다.
  • 실행에 오디오 변형(variant)이 지정돼 있으면 ffmpeg로 16 kHz 모노 WAV를 한 번 만들고, 필터 문자열을 적은 사이드카 파일과 함께 캐시한다.
  • ffmpeg volumedetect로 평균·최대 음량을 재고, 단계마다 out/STATUS.json에 기록을 쌓는다.
  • 실행별 옵션으로 stt_core.py를 띄우고, 출력을 노트북 화면과 out/<tag>/<file_id>.log에 동시에 남긴다.
  • 모든 실행이 끝나면 report_<control>.md를 쓰고 결과를 zip으로 묶어 브라우저로 내려받게 한 뒤 Drive 마운트를 해제한다.

What stt_core.py does insidestt_core.py 내부 단계

  1. Find speech with Silero VADfaster-whisper's get_speech_timestamps with the threshold you pass, 500 ms minimum silence and 300 ms padding.
  2. Silero VAD로 발화 구간 찾기faster-whisper의 get_speech_timestamps를 지정한 임계값, 최소 침묵 500 ms, 앞뒤 여유 300 ms로 호출한다.
  3. Build chunks up to 28 sSpeech spans less than 2 s apart are merged while the chunk stays under 28 s; longer spans are split. Whisper sees at most 30 s at a time.
  4. 28초 이하 조각 만들기간격이 2초 미만인 발화 구간은 28초를 넘지 않는 범위에서 합치고, 더 긴 구간은 자른다. Whisper가 한 번에 보는 길이가 최대 30초이기 때문이다.
  5. Fill the gaps VAD missed (optional)Uncovered stretches longer than --fill-gaps-s become extra chunks. Long gaps are cut at the quietest 0.2 s frame within the last 6 s of each 28 s window, so cuts rarely land mid-word.
  6. VAD가 놓친 구간 채우기 (선택)--fill-gaps-s보다 긴 빈 구간도 조각으로 만든다. 긴 구간은 28초 창의 마지막 6초 안에서 가장 조용한 0.2초 지점을 찾아 자르므로 단어 중간이 잘리는 일이 드물다.
  7. Group chunks into ~600 s blocksEach finished block is written to Drive as block_XXXX.json together with a SHA-256 hash of the settings, code and audio.
  8. 약 600초 블록으로 묶기끝난 블록은 설정·코드·오디오의 SHA-256 해시와 함께 block_XXXX.json으로 Drive에 저장된다.
  9. Choose the language per chunkdetect_language is limited to --languages. If the chunk is under 3 s with under 90% confidence, or the top two languages are within 0.15, the previous chunk's language is kept.
  10. 조각마다 언어 고르기detect_language 결과를 --languages 안에서만 비교한다. 조각이 3초 미만이면서 확신도가 90% 미만이거나, 1·2위 확률 차이가 0.15 미만이면 직전 조각의 언어를 그대로 쓴다.
  11. Build the promptHotwords in list order up to 120 tokens, plus up to 160 characters (80 tokens) from the end of the previous chunk. The context is used only if the language is the same, the gap is 5 s or less, and the previous chunk did not look like a hallucination (compression ratio ≤ 2.0, temperature ≤ 0.4).
  12. 프롬프트 만들기hotword를 목록 순서대로 120토큰까지 넣고, 직전 조각 끝부분을 최대 160자(80토큰)까지 이어 붙인다. 이 문맥은 언어가 같고, 간격이 5초 이하이며, 직전 조각이 환각처럼 보이지 않을 때(압축률 2.0 이하, temperature 0.4 이하)만 쓴다.
  13. DecodeBeam size 5, temperature fallback 0 → 1.0, word timestamps on, condition_on_previous_text off so one bad chunk cannot snowball.
  14. 디코딩beam 5, temperature fallback 0 → 1.0, 단어 타임스탬프 사용. 잘못된 조각 하나가 뒤로 번지지 않도록 condition_on_previous_text는 끈다.
  15. Filter and saveDrops a segment that repeats the previous one within the same chunk, optionally drops subtitle-credit phrases, then writes <file_id>.json with config, stats, chunks and segments.
  16. 걸러내고 저장같은 조각 안에서 바로 앞 세그먼트를 되풀이한 세그먼트를 지우고, 설정에 따라 자막 크레딧류 문구도 지운 뒤, 설정·통계·조각·세그먼트를 담은 <file_id>.json을 쓴다.

모든 파일은 Drive 폴더 하나 아래에 둔다. 노트북의 BOOTSTRAP 셀이 이 폴더를 만들고 저장소의 코드와 템플릿을 복사한다. 이미 고친 파일은 덮어쓰지 않는다.

Tip. Order matters. In the conference example a 42-term list lost 9 terms to the budget. Put the names a speaker says most often, and the ones Whisper gets wrong, at the top. Course slides, a meeting agenda or a talk abstract are good places to collect them. Real lists are in examples/real-run-conference/sessions.json.

팁. 순서가 중요하다. 컨퍼런스 예시에서는 42개짜리 목록 중 9개가 한도 밖으로 밀렸다. 화자가 자주 말하는 이름과 Whisper가 자주 틀리는 이름을 위로 올린다. 강의 슬라이드, 회의 안건, 발표 초록에서 용어를 모으면 편하다. 실제로 쓴 목록은 examples/real-run-conference/sessions.json에 있다.

Write a control filecontrol 파일 쓰기

A control file says what to run. Keeping it on Drive means you change the plan by dropping a new file there, without touching the notebook. Number them (control_001, control_002, …): the notebook picks the last one in sorted order and names the report and zip after it.

control 파일에는 무엇을 돌릴지 적는다. Drive에 두기 때문에 노트북은 그대로 두고 새 파일만 올려서 계획을 바꿀 수 있다. 번호를 붙여 둔다(control_001, control_002, …). 노트북은 이름순으로 가장 뒤에 있는 파일을 쓰고, 리포트와 zip 이름도 그 파일 이름을 따른다.

Pilot: try two settings on two minutes파일럿: 2분 구간으로 설정 두 개 비교

{
  "code_dir": "code",
  "audio_variants": { "loudnorm": "highpass=f=80,loudnorm=I=-18:TP=-2:LRA=11" },
  "run_pilot": true,
  "pilot_runs": [
    { "tag": "pilot_raw", "file_id": "01_lecture", "audio": "raw", "vad_audio": "raw",
      "start": 600, "duration": 120,
      "args": "--vad-threshold 0.35 --context-chars 160 --min-chunk-s 1.0 --fill-gaps-s 3" },

Run it in ColabColab에서 실행

  1. Open the notebook and pick a GPUUse the Open in Colab button, then Runtime → Change runtime type → T4 GPU.
  2. 노트북을 열고 GPU 선택Colab에서 열기 버튼을 누르고 런타임 → 런타임 유형 변경 → T4 GPU를 고른다.
  3. SETUPInstalls faster-whisper 1.2.1, PyAV 16.0.1, CTranslate2 4.8.5 and the CUDA 12 cuBLAS/cuDNN wheels, then puts their lib folders on LD_LIBRARY_PATH. The transcription subprocess inherits that variable.
  4. SETUPfaster-whisper 1.2.1, PyAV 16.0.1, CTranslate2 4.8.5와 CUDA 12용 cuBLAS/cuDNN 휠을 설치하고, 그 lib 폴더들을 LD_LIBRARY_PATH에 넣는다. 전사 하위 프로세스가 이 환경 변수를 물려받는다.
  5. BOOTSTRAP (first time)Mounts Drive, creates MyDrive/whisper_stt, copies the code, a sessions.json template and a pilot control file.
  6. BOOTSTRAP (처음 한 번)Drive를 마운트하고 MyDrive/whisper_stt를 만든 뒤 코드, sessions.json 템플릿, 파일럿 control 파일을 복사한다.
  7. Upload audio and edit the JSON filesPut recordings in audio/, describe them in code/sessions.json, adjust the control file. Editing in the Drive web UI or the Colab file browser both work.
  8. 오디오 올리고 JSON 고치기녹음을 audio/에 넣고, code/sessions.json에 설명을 적고, control 파일을 고친다. Drive 웹 화면에서 고쳐도 되고 Colab 파일 탐색기에서 고쳐도 된다.
  9. MOUNT_AND_LOADLoads the newest control file, prints the SHA-256 of stt_core.py and runner.py so you can confirm which version will run, and stops early if no GPU is visible.
  10. MOUNT_AND_LOAD가장 최근 control 파일을 읽고, 어떤 코드가 돌지 확인할 수 있게 stt_core.py와 runner.py의 SHA-256을 출력한다. GPU가 보이지 않으면 여기서 멈춘다.
  11. RUNPrints one progress line per block. When it finishes, the browser downloads stt_<control>.zip.
  12. RUN블록마다 진행 줄을 하나씩 출력한다. 끝나면 브라우저가 stt_<control>.zip을 내려받는다.
model_load_s=32.284300
block 0000 RUN audio_s=583.828 wall_s=58.684 rtf=0.100516
block 0001 RUN audio_s=1175.228 wall_s=114.635 rtf=0.097543
...
block 0008 RUN audio_s=4742.699 wall_s=542.209 rtf=0.114325

If Colab disconnects. Reconnect and run SETUP, MOUNT_AND_LOAD and RUN again with the same control file. Blocks already on Drive print SKIP instead of RUN. A block is reused only if the settings, code, audio and incoming context are all unchanged, so editing any flag reruns everything for that tag.

Colab 연결이 끊기면. 다시 연결해서 같은 control 파일로 SETUP, MOUNT_AND_LOAD, RUN을 차례로 실행한다. Drive에 이미 저장된 블록은 RUN 대신 SKIP으로 표시된다. 설정, 코드, 오디오, 넘겨받은 문맥이 모두 같을 때만 블록을 재사용하므로 옵션을 하나라도 바꾸면 그 tag는 처음부터 다시 돈다.

RUN unmounts Drive at the end so every write is flushed. To start another run in the same session, run MOUNT_AND_LOAD again first.

RUN은 마지막에 Drive 마운트를 해제해서 쓰기가 모두 반영되게 한다. 같은 세션에서 다시 돌리려면 MOUNT_AND_LOAD부터 다시 실행한다.

One segment in the JSON looks like this (trimmed):

  "id": 41, "chunk": 17, "source": "gap",
  "start": 512.84, "end": 518.3, "language": "en",

source tells you whether the chunk came from VAD or from gap filling. Low avg_logprob or a non-zero temperature marks lines worth checking against the recording. To get a plain transcript or subtitles:

python code/export_text.py out/full_v3/01_lecture.json   # → .txt and .srt
